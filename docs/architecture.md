# Архитектура

Формат файла описан в [safebox-format.md](safebox-format.md), API в [api.md](api.md).

## Слои

Проект разбит на слои, каждый слой это отдельный CMake-таргет:

```
safeboxd (src/daemon)
  |-- safebox-http (src/http)          REST на cpp-httplib
  |     `-- safebox-core = domain + application
  `-- safebox-infra (src/infrastructure)   sqlite, libsodium, stb, libwebp, miniz
        `-- safebox-domain
```

- `domain` - header-only, без зависимостей. Модель записи (`Entry`, `Kind`), ошибки,
  правила (пароль, имена, тип файла по сигнатуре), константы формата и порты -
  интерфейсы `CryptoSuite`, `VaultStore`, `Thumbnailer`, `ZipWriter`, `Clock`.
- `application` - сервисы `SafeService`, `EntriesService`, `ImportExportService`,
  `SearchService`, сессия и автоблокировка. Знает только domain.
- `infrastructure` - реализации портов. Все сторонние либы подключены PRIVATE,
  наружу торчит только `factories.hpp`.
- `http` - роутер, проверки Host/Origin, авторизация, контроллеры. Infra не видит.
- `daemon` - `main.cpp` и конфиг. Единственное место, где встречаются http и infra,
  тут адаптеры передаются в сервисы.

Раз зависимости держатся на таргетах, то `#include <sqlite3.h>` в application просто
не соберется. `scripts/ci.sh` дополнительно проверяет инклюды grep-ом.

Почему sqlite, а не postgres: сейф должен быть одним файлом, который можно скопировать
на флешку и открыть на другом компе. Шифруем мы сами до записи в базу, так что от
базы нужны только транзакции и хранение байтов.

## Сессия и блокировка

Запросы обрабатываются параллельно в пуле потоков httplib. Открытый сейф это
`VaultSession`: ключи, номер поколения (epoch), токены и кеш расшифрованных имен.

Каждый запрос начинается с `SafeService::authorize(token)`, который возвращает
`Lease` (аренду). Аренда держится до конца запроса, включая долгий стрим видео или
импорт.

`lock` (кнопка, автоблокировка, выход) делает так:
1. увеличивает epoch, старые токены сразу перестают работать (401)
2. ставит флаг отмены, импорт и стримы проверяют его между кусками
3. ждет, пока все аренды отпустят
4. отпускает ключи, последняя ссылка стирает их (`sodium_free`)
5. удаляет недописанные блобы и закрывает файл

Автоблокировка: фронт раз в 20с шлет `POST /safe/heartbeat {active}`. 15 минут без
активности или 2 минуты вообще без heartbeat (закрыли вкладку) - lock. Считается по
монотонным часам, логика в `IdlePolicy`, тестируется на `FakeClock`.

## Импорт и чтение

Импорт идет потоком: httplib отдает части multipart колбэками, они сразу уходят в
`ImportSession`. Файл режется на куски по 8 МиБ, каждый кусок шифруется и пишется
своей короткой транзакцией в блоб со статусом pending. Когда файл закончился,
делается миниатюра и одной транзакцией создается запись и блоб переводится в ready.
Если один файл упал, удаляется только его pending, остальные идут дальше. Память не
растет от размера файла.

Относительные пути приходят в `filename` (webkitRelativePath), папки находятся по
имени без учета регистра или создаются. Ссылки попадают в сейф импортом `.url` ярлыков.

Повторный импорт той же папки докачивает только новое. Если в папке уже есть файл с
тем же именем, его куски расшифровываются и сравниваются с новыми по мере записи;
совпал до байта - новый pending выбрасывается и считается в `skipped`. Хешей в мете
нет, поэтому сравнение честное, но стоит чтения старого файла.

Range для видео разбирает httplib. Мы переводим смещение в номера кусков и
расшифровываем только нужные, последний кусок кешируется.

Экспорт папки - zip потоком (STORE + data descriptor + ZIP64). Zip пишем сами, от
miniz берем только crc32: miniz пишет с seek, а в http-ответ seek не сделаешь.

Поиск идет по кешу расшифрованных имен, кеш сбрасывается при импорте, переименовании
и удалении и стирается при lock.

## Ошибки

Везде `std::expected<T, Error>`. В HTTP-коды переводится в `src/http/src/errors.cpp`,
таблица есть в [api.md](api.md). Важно: 401 отдается только когда сессия мертвая (фронт
по 401 показывает экран входа), неверный пароль это 403.

## Безопасность сервера

На 127.0.0.1 может постучаться любая страница из браузера, поэтому:
- слушаем только 127.0.0.1, доступ по локалке включается явно (`--host`, без HTTPS)
- `Host` только из белого списка (защита от DNS rebinding)
- на изменяющих запросах проверяется `Origin` и `Sec-Fetch-Site`
- JSON-эндпоинты принимают только `application/json`
- API по Bearer токену. Для `<img>`/`<video>` есть отдельный токен в HttpOnly cookie,
  он работает только на GET `/api/v1/media/*`. Токены в URL не передаются.

## Тесты

- application - сервисы на `InMemoryVaultStore` и `FakeClock`, но с настоящим libsodium
  (фейковый шифр не поймал бы ошибки с AAD)
- http - на фейковых сервисах, запросы подаются в httplib без сокетов
- infra - настоящие sqlite, libsodium, stb и libwebp, zip (архив читается miniz)
- integration - весь стек на случайном порту: create, import, list, search, range, zip,
  lock, потом проверка что копия файла открывается

ASan гоняется на MSVC, UBSan только на clang.

## Что не сделано

В ТЗ нет сценария создания пустой папки и ссылки вручную, поэтому `createFolder`,
`createLink` и `move` пока нет. Структура папок (`parent_id`) хранится открыто и не
защищена от подмены, откат файла к старой копии тоже не обнаруживается.
